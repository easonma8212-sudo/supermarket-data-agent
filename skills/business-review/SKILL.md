# 经营概览与变化拆解

调用 `run_business_review`，参数仅为当前期间 start_date、end_date。
用户未给期间时使用最近完整7天；相对日期以数据最新完整日为锚点。
仅支持全店、完整日和此前等长期间；指定商品、类别或任意比较期间不能悄悄省略筛选。

执行程序完成以下步骤：
1. 校验两段期间均在数据覆盖范围内，当前期间最多31天。
2. 读取两期销售额、小票数、有效交易日和缺失字段计数。
3. 按类别及商品分别计算当前金额、此前金额、差额，涵盖两期所有实体后再取涨跌各前3名。
4. 校验两种拆分的差额合计分别与全店差额一致；严重字段缺失或对账失败时停止经营结论。
5. 用固定模板报告金额和比例变化、正负贡献及待核实事项。

类别和商品是两种独立拆分，不可相加。差额贡献不是因果解释；不推断缺货、促销、天气或客流原因。
小票数不是人数。全店客单价为销售额除以有效小票数；此前为0时不计算增长率。
无销售记录的日期只能提示核实营业或导入情况，不得认定数据完整。
不把销售数量跨不同计量单位相加作为经营结论。

首版是 LLM 选 Skill、程序执行固定流程；不做根据结果自由追加查询，不把汇总证据送回模型。
执行器在 `app/business_review.py`；核心指标沿用 `docs/metric_catalog.md` 的口径。
