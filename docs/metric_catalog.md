# 超市 NL2Metrics 指标语义目录

本目录定义网页通用指标查询允许使用的业务语义。LLM 只能生成这里列出的指标、维度、筛选和时间参数；本机编译器负责校验并生成参数化只读 SQL。

## 指标

| 指标编号 | 中文名称 | 固定口径 |
| --- | --- | --- |
| `sales_amount` | 销售额 | `sum(actual_amount)` |
| `sales_quantity` | 销量 | `sum(quantity)` |
| `receipt_count` | 小票数 | `count(distinct receipt_no)` |
| `average_receipt_amount` | 客单价 | 销售额 ÷ 小票数 |
| `average_selling_price` | 平均售价 | 销售额 ÷ 销量 |

这些口径基于当前 POS 销售明细副本。利润、毛利和库存数量不在本目录中。

当筛选商品/类别或按商品/类别分组时，`average_receipt_amount` 表示每张相关小票的所选商品金额，界面使用此名称；它不是相关顾客整张购物小票的金额。全店无筛选时才称“全店客单价”。

## 维度

| 维度编号 | 含义 | 当前限制 |
| --- | --- | --- |
| `product` | 按商品编号分组 | 同时展示商品名称和类别 |
| `category` | 按商品类别分组 | 类别使用 POS 原始分类值 |
| `day` | 按销售日期分组 | 无排行要求时返回完整期间，最多50天 |
| `null` | 不分组汇总 | 返回一行汇总结果 |

第一版每次只允许一个维度，暂不支持商品×日期等二维交叉表。

## 筛选

- `product_query`：用户输入的商品名称或商品编号。程序先进行本机实体解析，唯一匹配后转换为 `item_no`；多匹配或无匹配时要求澄清。
- `category`：POS 中的精确类别名称。SQL 使用参数传递，不拼接用户文本。

## 时间与对比

- 默认趋势和排行截止最新完整数据日。
- `allow_partial_end_date=true` 只用于用户明确要求今天或最新数据日。
- `comparison=previous_period` 使用紧邻当前期间之前的等长期间。
- 普通“卖得怎么样”不自动增加对比；只有明确出现对比、变化、增长或下降要求时才使用前期对比。

## 排序与限制

- `order_by` 只能引用本次已经选择的认证指标。
- 排序方向只允许 `asc` 或 `desc`。
- 每次最多返回50行。
- 日期趋势没有指标排行要求时，编译器自动把行数规范为请求天数，避免模型错误地只返回一天。

## 当前仍使用专用工具的能力

- 按跨期差值查找上升或下降最多的商品。
- 计算类别销售额占总销售额的贡献率。

这两类需要差值排行或窗口占比，后续会在通用语义层中建模。现阶段保留专用工具，避免为了表面统一而降低口径可靠性。
