# 首版补货关注清单方法

## 输出含义

`analytics.replenishment_attention` 根据最近 28 天销售数量计算日均销售速度，再估算指定覆盖期内可能售出的数量。

它回答的是“如果未来销售速度与最近 28 天相近，需要准备多少件商品覆盖这段时间”，不是“现在应该下单多少件”。由于 POS 没有维护可信库存，最终订货量仍需人工查看货架、库房和在途商品。

## 当前规则

| 采购方式 | 已映射类别 | 默认情景 |
|---|---|---|
| 本地供应商 | 饮料、酒水、农夫水、礼盒奶、零食 | 未来 7 天预计需求 |
| 自行采购 | 日化、家居百货、文具类 | 未来 30 天和 60 天预计需求 |
| 待人工分类 | 其余类别 | 不计算覆盖量 |

计算基础：

```text
最近28天日均销量 = 最近28天销售数量 / 28
预计覆盖需求 = 向上取整(最近28天日均销量 × 覆盖天数)
趋势比 = 最近28天销量 / 前一个28天销量
```

使用 28 个自然日作为分母，包括没有销售的日期，避免只统计有销量的日子而夸大需求。

## 使用限制

- 结果未扣除现有库存和在途采购。
- 结果未考虑整箱规格、最小订货量、保质期和节假日增量。
- “预置类”包含大量未正确分类商品，首版不做自动采购渠道推断。
- 特价拼单等虚拟货号暂时保留在待人工分类范围，不建议直接采购。
